# Defender II Windows / Godot 需求文档

版本：3.1-godot-windows

文档日期：2026-09-03

对应分支：`windows-godot`

状态：轻量 Windows 单机 MVP 实施基线

实施状态：MVP 代码、Windows x86_64 EXE/PCK、便携 ZIP 和本机普通用户运行验收均已完成，AT-001～AT-020 全部通过。逐项证据见 [`implementation-status.md`](implementation-status.md)。

研究归档：`main` 分支、标签 `archive/mobile-cross-platform-v2.0`

## 1. 产品决策与边界

### 1.1 产品目标

开发一款受 DroidHen《Defender II》启发的 Windows 2D 城堡防守单机游戏。玩家用鼠标瞄准并持续射击，配合法术、城墙和局外升级抵御逐渐增强的敌人波次。

首版只验证一个可持续扩展的本地闭环：

```text
开始游戏 -> 战斗 -> 胜利/失败 -> 获得资源 -> 升级 -> 下一关
```

详细玩法证据、历史版本和冲突数值保存在归档分支。本分支不复制移动平台、在线模式和运营系统，只保留单机实现需要的结论。

### 1.2 平台与技术方案

| 项目 | 决策 |
|---|---|
| 首发平台 | Windows 10 / Windows 11，x86_64 |
| 引擎 | Godot 4.7.2 stable 标准版 |
| 语言 | GDScript |
| 渲染 | Compatibility Renderer，2D Canvas |
| 画面 | 2D 横屏，默认 1920×1080，可缩放窗口 |
| 输入 | 鼠标必需；键盘快捷键必需；手柄后置 |
| 游戏模式 | 本地单机 Local |
| 存档 | `user://` 下的 JSON + 备份文件 |
| 发布 | Windows x86_64 EXE/PCK 便携 ZIP |

采用 Godot 标准版和 GDScript，不安装 .NET SDK、Visual Studio、Android/iOS 工具链或第三方插件。只有内置工具无法满足已验收需求时才允许增加 addon。

### 1.3 MVP 成功标准

- 新玩家在 60 秒内完成瞄准、连续射击和一次法术施放。
- 至少 10 个线性 Stage 可以完整运行到胜负结算。
- 所有 MVP 功能断网可用，不显示账号、商店或服务器入口。
- 崩溃或断电后仍能读取最近有效存档或备份。
- 同一 `stageId + seed + configVersion + commandLog` 产生一致的胜负和奖励。
- 当前开发机 i5-8400、16GB、GTX 1060 在 1080p 稳定达到 60 FPS。
- 100 个敌人、200 个投射物压力场景中输入和结算保持正确。
- 一条命令可执行无窗口测试并导出 Windows 调试包。

### 1.4 首版范围门禁

以下能力不属于 MVP：

- Unity 或其他第二引擎并行实现。
- Android、iOS、macOS、Web 和主机版本。
- Battle、实时联机、排行榜、账号和专用服务器。
- 云存档、数据库、遥测平台和远程配置。
- 广告、应用内购买、Steam SDK 和平台成就。
- C#/.NET、Visual Studio 和重量级第三方框架。
- DLC、Mod、创意工坊和自动更新。

新增范围必须通过 ADR 说明用户价值、安装成本、维护成本、存档影响和可撤销方案。

## 2. 用户与核心用例

| 角色 | 核心用例 |
|---|---|
| 新玩家 | 启动、教学、Stage、瞄准、射击、施法、结算 |
| 熟练玩家 | 选择武器/技能、升级、重玩关卡、挑战 Boss |
| 内容设计者 | 编辑敌人、波次、技能和奖励数据并运行校验 |
| QA | 运行固定 seed、存档恢复、分辨率和性能场景 |

## 3. 功能需求

### 3.1 启动、档案与设置

**FR-001 首次启动**

系统 MUST 在 `user://` 创建默认 `PlayerProfile`、唯一 `installId`、设置和所需目录。初始化失败必须提供可重试提示，不得留下半成品存档。

**FR-002 本地存档**

升级购买、Stage 结算和设置变化后 MUST 保存。保存流程为临时文件、校验、替换主档并保留上一份备份。

**FR-003 存档恢复**

主档缺失、JSON 解析失败或 hash 不一致时，系统 MUST 尝试 `.bak`。损坏文件保留为诊断副本，不能在启动循环中持续覆盖。

**FR-004 版本迁移**

存档包含 `schema_version`。迁移按版本逐级运行；失败时允许恢复备份、开始新档或退出。

**FR-005 设置**

至少提供主音量、音乐、音效、语言、全屏/窗口、分辨率、画面质量、瞄准辅助、悬停自动射击和屏幕震动开关。设置立即生效并保存。

### 3.2 菜单与 Stage

**FR-010 主菜单**

MVP 只显示继续游戏、选择 Stage、升级、设置、教学和退出。未实现功能不得显示灰色占位按钮。

**FR-011 Stage 选择**

玩家可以开始当前已解锁 Stage 或重玩已通过 Stage。入口显示 Stage 编号、Boss 标记、最佳结果和奖励预览。

**FR-012 Stage 胜负**

配置目标完成且 Boss 已处理时胜利；城墙 HP 归零时失败。同一物理 tick 同时满足条件时，按照固定事件顺序裁决。

**FR-013 结算**

结算显示胜负、Stage、波次、击杀、剩余城墙百分比、金币、XP 和新解锁，并带玩家等级经验进度条（`Lv.N` + 本级进度 `into/needed`，升级时提示 `Lv.A → B`）。失败局保留已获得的击杀金币。

**FR-014 暂停与退出**

Esc 暂停并显示继续、重新开始、设置和返回菜单。返回菜单前需要确认，退出不得错误触发胜利奖励。

### 3.3 战斗场景与输入

**FR-020 战场**

城堡和弩炮位于左侧，敌人从右侧不同纵向位置进入连续 2D 战场。不得使用固定 lane 限制敌人位置。

**FR-021 瞄准**

InputMap 的鼠标位置转换为逻辑战场坐标。窗口缩放、全屏切换和不同宽高比下，准星与射击方向 MUST 一致。

**FR-022 悬停自动射击**

光标悬停在战场区域(未悬停任何交互控件)时,系统按武器射击间隔持续产生箭矢,方向跟随光标移动;光标移入 HUD 控件(技能按钮除外,悬停技能按钮不中断射击)、暂停/结算/设置覆盖层打开、选中法术或正在拖拽施法时立即停止。设置提供"悬停自动射击"开关,关闭后回退为按住左键连续射击的经典模式。

**FR-023 法术输入**

数字键 `1/2/3` 选择火、冰、雷技能。选择后按住左键在战场上拖拽(模拟移动端手指拖动),拖拽过程实时显示范围指示圈并按合法性着色(合法目标绿色,越界/Mana 不足/冷却中红色),松开左键在释放点施放;在 UI 控件上松开则取消施放。右键或 Esc 随时取消选中和拖拽。Mana 不足、冷却中或目标非法时不得生成效果。

**FR-024 反馈**

射击、命中、Fatal Blow、Power Shot、元素效果、Mana 不足、Boss 预警、城墙受击和胜负必须有视觉或音频反馈，不能只依赖颜色。

### 3.4 武器、技能与防御

**FR-030 Strength**

Strength 提高新生成箭矢伤害；飞行中的箭矢使用生成时属性快照。

**FR-031 Agility**

Agility 缩短射击间隔，但不得低于配置的最小间隔。

**FR-032 武器**

MVP 包含基础弓；Windows 1.0 增加 Power、Hurricane、Phantom。武器数据包含伤害、射速、弹速、击退、穿透和特殊效果。

**FR-033 Power Shot**

触发时对合法目标施加可配置击退。Boss 抗性和边界行为来自配置。

**FR-034 Fatal Blow**

按配置概率让本次最终箭矢伤害变为 2 倍，并显示 `Fatal!`；不得默认实现一击必杀。

**FR-040 元素技能**

MVP 提供 Fire Ball、Glacial Spike、Lightning Strike。火系偏范围持续伤害，冰系偏减速/冻结，雷系偏打断；数值和抗性由配置提供。

**FR-041 Mana**

Mana 始终限制在 `[0, max_mana]`。施法扣除、自然恢复和其他来源由配置控制。

**FR-050 城墙**

城墙显示当前/最大 HP。敌人抵达攻击点后按间隔造成伤害；HP 归零后停止生成并触发失败。

**FR-051 后续防御设施**

Lava Moat 和 Magic Tower 属于 Windows 1.0，不阻塞 MVP。接入时必须是独立可选系统。

### 3.5 敌人、波次与 Boss

**FR-060 敌人模型**

敌人至少包含 HP、速度、攻击伤害、攻击间隔、护甲、连续位置、攻击点、标签和状态抗性。

**FR-061 敌人模板**

MVP 包含近战、快速、远程三种普通敌人和一个 Boss。Windows 1.0 可增加重甲、飞行和更多 Boss。

**FR-062 生成**

`SpawnSystem` 根据 Stage 配置生成总量、组成、间隔、纵向范围和 Boss。同一 seed 的生成顺序必须一致。

**FR-063 难度曲线**

难度可以提高 HP、伤害、速度、数量和组合复杂度，各项必须有上限，不得只无限提高 HP。

**FR-064 Boss**

Boss 有名称、独立血条、预警、至少一个特殊行为和唯一结算事件。死亡和奖励只能处理一次。

### 3.6 成长与经济

**FR-070 资源**

MVP 使用 `coins` 和 `xp`；`crystals` 可以保留为非付费玩法字段。奖励必须包含来源、数量、规则版本和幂等键。XP 同时驱动玩家等级：第 N 级需 `100 × N` 经验，主菜单与结算面板显示 `Lv.N` 与升级进度条（等级由 XP 实时推导，存档无需迁移）。

**FR-071 升级**

升级页显示当前等级、下一等级效果、价格、前置条件和上限。购买必须原子扣费，余额不足不得部分修改。

**FR-072 MVP 研究**

MVP 至少实现 Strength、Agility 和三个基础元素技能等级。完整四页研究树、更多武器和 Honors 进入 Windows 1.0。

**FR-073 奖励幂等**

结算使用 `run_id + reward_version` 作为幂等键。重复加载或保存不得重复增加资源。

### 3.7 配置、随机与诊断

**FR-080 数据驱动**

敌人、Stage、武器、技能、升级和奖励不得散落为脚本常量。规则配置声明 `config_version`、`ruleset_version` 和来源。

**FR-081 配置校验**

启动和导出前校验 ID、引用、数值范围、升级前置和 Stage 完整性。开发环境阻止坏配置运行，发布包回退到内置有效配置。

**FR-082 确定性随机**

每局保存 `run_id`、`stage_id`、`seed`、配置版本和必要命令。规则脚本不得直接调用未注入 seed 的随机方法。

**FR-083 调试回放**

调试构建可导出命令日志和事件 hash。MVP 不向玩家提供回放 UI。

## 5. 非功能需求

**NFR-001 性能**：领域模拟固定 30 tick/s，目标渲染 60 FPS；100 敌人和 200 投射物时逻辑 p95 < 10 ms。

**NFR-002 启动**：SSD 冷启动到主菜单目标 < 4 秒。

**NFR-003 内存**：1080p 单局工作集目标 < 750MB；连续 60 分钟不得持续增长。

**NFR-004 离线**：MVP 不产生强制网络请求。

**NFR-005 可靠性**：主档、备份和迁移均有无窗口自动测试；坏存档不得造成启动崩溃循环。

**NFR-006 可维护性**：核心规则脚本继承 `RefCounted` 或使用纯数据，不依赖场景树路径、输入单例或表现节点。

**NFR-007 可复现**：固定 seed、配置和命令日志产生一致的规则事件、胜负和奖励。

**NFR-008 可访问性**：重要信息不能只使用颜色；支持 UI 缩放、音量/震动关闭和瞄准辅助。

**NFR-009 本地化**：MVP 支持简体中文和英文，所有可见文本使用 key。

**NFR-010 构建**：Windows x86_64 导出记录 Godot 版本、配置 hash 和 Git SHA。

**NFR-011 隐私**：MVP 不收集、上传或共享玩家数据。

**NFR-012 依赖**：MVP 生产代码不依赖 Asset Library addon；任何新增插件必须锁定来源和版本。

## 6. 软硬件要求

### 6.1 开发环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 x64 |
| CPU | 4 核推荐；当前 i5-8400 满足 |
| 内存 | 4GB 最低，8GB 推荐；当前 16GB 满足 |
| GPU | Compatibility Renderer 需要 OpenGL 3.3/D3D11 同级；GTX 1060 满足 |
| 磁盘 | 引擎、模板和缓存约 1.5GB；项目另预留 3～10GB |
| 软件 | Godot 4.7.2 标准版、Windows export templates、Git |

不要求 Unity Hub、Visual Studio、.NET SDK、Android Studio、Xcode、Docker 或数据库。可直接使用 Godot 内置脚本编辑器。

### 6.2 玩家建议配置

| 等级 | 操作系统 | CPU | 内存 | GPU | 存储 |
|---|---|---|---|---|---|
| 最低目标 | Windows 10 x64 | 双核 | 4GB | Intel UHD 630 或 D3D11/OpenGL 3.3 同级 | 1GB |
| 推荐 | Windows 10/11 x64 | 四核 | 8GB | GTX 750/GT 1030 或更高 | 1GB |

最终最低配置必须经过独立低配机验证。

## 8. 交付顺序

1. Godot 工程、目录、Autoload 组合根、无窗口测试和导出预设。
2. 垂直切片：基础弓、一个敌人、城墙和胜负。
3. 三种敌人、三种技能、10 Stage 和 Boss。
4. JSON 存档、升级、配置校验、回放金样和设置。
5. 性能、低配兼容、Windows ZIP 和版本清单。
6. MVP 验收后再决定 Windows 1.0 内容。

## 9. 发布门禁

- AT-001 至 AT-020 全部通过。
- 无窗口规则、配置和存档测试返回成功退出码。
- 发布包不包含调试菜单、测试档、绝对路径或个人信息。
- EXE/PCK 在未安装 Godot 的 Windows 电脑上可运行。
- ZIP 包包含版本、配置 hash、许可和最小运行要求。
- 未实现能力不以空按钮或联网错误暴露给玩家。
