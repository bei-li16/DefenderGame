# Defender II Windows / Unity 需求文档

版本：3.0-unity-windows

文档日期：2026-09-01

对应分支：`windows-unity`

状态：Windows 单机 MVP 实施基线

研究归档：`main` 分支、标签 `archive/mobile-cross-platform-v2.0`

## 1. 产品决策与边界

### 1.1 产品目标

开发一款受 DroidHen《Defender II》启发的 Windows 2D 城堡防守单机游戏。玩家用鼠标瞄准并持续射击，配合法术、城墙和局外升级抵御逐渐增强的敌人波次。

首版优先验证以下闭环：

```text
开始游戏 -> 战斗 -> 胜利/失败 -> 获得资源 -> 升级 -> 下一关
```

玩法研究、历史证据和冲突数值完整保存在归档分支。本分支只记录 Windows 实施所需需求；原作未公开的公式继续作为可调建议值，不宣称是原作精确数据。

### 1.2 平台与技术方案

| 项目 | 决策 |
|---|---|
| 首发平台 | Windows 10 21H1+ / Windows 11，x64 |
| 引擎 | Unity 6.3 LTS |
| 语言 | C# |
| 画面 | 2D 横屏，默认 1920×1080，可缩放窗口 |
| 输入 | 鼠标必需；键盘快捷键必需；手柄为后续增强 |
| 游戏模式 | 本地单机 Local |
| 存档 | 本地 JSON + 备份文件 |
| 发布 | 便携 ZIP；安装器和商店接入后置 |

### 1.3 MVP 成功标准

- 新玩家在 60 秒内完成瞄准、射击和一次法术施放。
- 至少 10 个线性 Stage 可从开始完整运行到结算。
- 断网时所有 MVP 功能可用，不出现登录或服务不可用提示。
- 崩溃或断电不会破坏最后一个有效存档。
- 同一 `stageId + seed + configVersion + commandLog` 可重放出一致的胜负和奖励。
- 在当前开发机 i5-8400、16GB、GTX 1060 上以 1080p 稳定达到 60 FPS。
- 100 个敌人、200 个投射物压力场景不影响输入响应和结算正确性。

### 1.4 首版范围门禁

以下能力明确不属于 MVP，也不得作为开始核心玩法开发的前置条件：

- Android、iOS、macOS、WebGL 和主机版本。
- Battle、实时联机、排行榜和专用服务器。
- 账号、云存档、UGS、业务后端、数据库和 Redis。
- 广告、应用内购买、付费货币和平台收据。
- Steam SDK、成就同步、创意工坊和自动更新。
- Addressables 远程内容、热更新和 Remote Config。

新增上述能力必须先提交独立 ADR，说明用户价值、维护成本、退出方案和对存档格式的影响。

## 2. 用户与核心用例

| 角色 | 核心用例 |
|---|---|
| 新玩家 | 启动游戏、完成教学、开始 Stage、射击、施法、查看结算 |
| 熟练玩家 | 选择武器和技能、升级属性、挑战 Boss、重玩 Stage |
| 内容设计者 | 修改敌人、波次、技能、升级和奖励配置并执行校验 |
| QA | 使用固定 seed 重放问题、验证存档恢复、执行性能压力场景 |

## 3. 功能需求

### 3.1 启动、档案与设置

**FR-001 首次启动**

系统 MUST 创建唯一 `installId`、默认 `PlayerProfile`、默认设置和存档目录。初始化失败时显示可重试错误，不得留下半成品存档。

**FR-002 本地存档**

升级购买、Stage 结算和设置变化后 MUST 保存。保存采用“临时文件 -> 校验 -> 原子替换 -> 保留上一份备份”的流程。

**FR-003 存档恢复**

主存档不存在、格式错误或校验失败时，系统 MUST 尝试读取 `.bak`。恢复前不得覆盖损坏文件，并应显示非技术化提示。

**FR-004 版本迁移**

存档包含 `schemaVersion`。旧版本按顺序迁移；迁移失败时保留原档并允许开始新档或退出。

**FR-005 设置**

至少提供主音量、音乐、音效、语言、全屏/窗口、分辨率、画面质量、瞄准辅助和屏幕震动开关。设置立即生效并跨会话保存。

### 3.2 菜单与 Stage

**FR-010 主菜单**

MVP 主菜单 MUST 提供继续游戏、选择 Stage、升级、设置、教学和退出。未实现的在线或商店功能不得显示占位入口。

**FR-011 Stage 选择**

玩家可以开始当前已解锁 Stage 或重玩已通过 Stage。入口显示 Stage 编号、Boss 标记、最佳结果和主要奖励。

**FR-012 Stage 胜负**

配置目标完成且 Boss 已处理时胜利；城墙 HP 归零时失败。同一 tick 同时满足条件时，按照固定事件顺序裁决并写入回放。

**FR-013 结算**

结算显示胜负、Stage、波次、击杀、剩余城墙百分比、金币、XP 和新解锁内容。失败局保留已获得的击杀金币。

**FR-014 暂停与退出**

Esc 暂停并显示继续、重新开始、设置、返回菜单。返回菜单前需要确认；确认后不得错误发放胜利奖励。

### 3.3 战斗场景与输入

**FR-020 战场**

城堡和弩炮位于左侧，敌人从右侧不同纵向位置进入连续 2D 区域。实现不得把战场限制成固定 lane。

**FR-021 瞄准**

鼠标位置转换为连续世界坐标并夹紧到战场范围。窗口缩放、全屏切换和不同宽高比下，准星与实际命中方向 MUST 一致。

**FR-022 连续射击**

按住鼠标左键时，系统按武器射击间隔持续生成箭矢；移动鼠标实时改变后续箭矢方向；松开、暂停、死亡或离开场景立即停止。

**FR-023 法术输入**

数字键 `1/2/3` 选择火、冰、雷技能，鼠标左键确认目标，右键或 Esc 取消。Mana 不足、冷却中或目标非法时不产生效果并显示原因。

**FR-024 反馈**

射击、命中、Fatal Blow、Power Shot、元素效果、Mana 不足、Boss 预警、城墙受击和胜负必须有可辨识的视觉或音频反馈，不能只依赖颜色。

### 3.4 武器、技能与防御

**FR-030 Strength**

Strength 提高新生成箭矢的伤害。已在飞行的箭矢使用生成时属性快照。

**FR-031 Agility**

Agility 缩短射击间隔，但不得低于配置的最小间隔。

**FR-032 武器**

MVP 包含基础弓；版本 1 增加 Power、Hurricane 和 Phantom。每件武器显示伤害、射速、弹速、击退、穿透和特殊效果。

**FR-033 Power Shot**

触发时对合法目标施加可配置击退。Boss 抗性和边界处理必须数据驱动。

**FR-034 Fatal Blow**

按配置概率使本次最终箭矢伤害变为 2 倍，并显示 `Fatal!`。默认行为不得实现成一击必杀。

**FR-040 元素技能**

MVP 提供 Fire Ball、Glacial Spike、Lightning Strike 三个基础技能。火系偏范围持续伤害，冰系偏减速/冻结，雷系偏打断；Mana、冷却、范围和抗性均来自配置。

**FR-041 Mana**

Mana 始终限制在 `[0, maxMana]`。施法扣除 Mana，再生和补充规则由配置控制。

**FR-050 城墙**

城墙显示当前/最大 HP。敌人抵达攻击点后按攻击间隔造成伤害；HP 归零触发失败并停止生成新敌人。

**FR-051 后续防御设施**

Lava Moat 和 Magic Tower 属于版本 1，不阻塞 MVP。接入时必须作为可选实体，不得改写敌人或城墙的核心状态机。

### 3.5 敌人、波次与 Boss

**FR-060 敌人模型**

敌人至少包含 HP、速度、攻击伤害、攻击间隔、护甲、位置、攻击点、标签和状态抗性。

**FR-061 敌人模板**

MVP 包含近战、快速、远程三种普通敌人和一个 Boss。版本 1 可增加重甲、飞行和更多 Boss。

**FR-062 生成**

`SpawnDirector` 根据 Stage 配置生成总量、组成、间隔、纵向范围和 Boss。相同 seed 的生成顺序必须一致。

**FR-063 难度曲线**

难度可以提高 HP、伤害、速度、数量和组合复杂度，但每项有上限。不得只依赖无限提高 HP 制造难度。

**FR-064 Boss**

Boss 有独立名称、血条、预警、至少一个特殊行为和唯一结算事件。死亡事件和奖励只能处理一次。

### 3.6 成长与经济

**FR-070 资源**

MVP 使用 `coins` 和 `xp`；`crystals` 可保留在数据模型中但不与付费绑定。所有奖励包含来源、数量、规则版本和幂等键。

**FR-071 升级**

升级页显示当前等级、下一等级效果、价格、前置条件和上限。购买操作原子扣费；余额不足不得发生部分修改。

**FR-072 MVP 研究**

MVP 至少实现 Strength、Agility 和三个基础元素技能等级。完整四页研究树、更多武器和 Honors 进入版本 1。

**FR-073 奖励幂等**

结算使用 `runId + rewardVersion` 作为幂等键。重复加载结算或重复保存不得再次增加资源。

### 3.7 配置、随机与诊断

**FR-080 数据驱动**

敌人、Stage、武器、技能、升级和奖励不得散落为代码常量。配置必须声明 `configVersion`、`rulesetVersion` 和来源字段。

**FR-081 配置校验**

启动和构建前校验 ID 唯一、引用存在、数值范围、升级前置无环、Boss/Stage 引用有效。失败时开发构建应阻止运行，发布构建回退到内置有效配置。

**FR-082 确定性随机**

每局保存 `runId`、`stageId`、`seed`、`configVersion` 和必要命令。领域逻辑不得直接读取系统随机数或渲染帧时间。

**FR-083 调试回放**

开发构建可导出轻量回放文件。MVP 只要求用于 QA 和自动化测试，不要求向玩家提供回放 UI。

## 5. 非功能需求

**NFR-001 性能**：固定模拟 30 tick/s；目标渲染 60 FPS。100 敌人和 200 投射物时逻辑 p95 < 10 ms。

**NFR-002 启动**：安装在 SSD 时，冷启动到主菜单目标 < 5 秒。

**NFR-003 内存**：1080p 单局工作集目标 < 1GB；连续 60 分钟不得持续增长。

**NFR-004 离线**：MVP 不进行任何强制网络请求。

**NFR-005 可靠性**：主存档、备份和迁移路径均有自动化测试；损坏存档不得导致无限崩溃循环。

**NFR-006 可维护性**：Domain 程序集不得引用 `UnityEngine`；表现层不能直接修改 Profile 和奖励余额。

**NFR-007 可复现**：固定 seed、配置和命令日志产生一致的领域事件、胜负和奖励。

**NFR-008 可访问性**：重要信息不能只使用颜色；支持 UI 缩放、音量关闭、屏幕震动关闭和可配置瞄准辅助。

**NFR-009 本地化**：MVP 支持简体中文和英文；所有可见文本使用本地化 key。

**NFR-010 构建**：Windows x64 构建由脚本或 Build Profile 生成，记录 Unity 版本、包锁、配置哈希和 Git SHA。

**NFR-011 隐私**：MVP 不收集、上传或共享玩家数据。
**NFR-012 兼容性**：发布包支持 Windows 10 21H1+ 和 Windows 11 x64，默认使用 DX11；不承诺 32 位 Windows。

## 6. 软硬件要求

### 6.1 开发环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 x64 |
| CPU | 4 核以上；当前 i5-8400 满足 |
| 内存 | 8GB 最低，16GB 推荐；当前配置满足 |
| GPU | 支持 DX11；当前 GTX 1060 满足 |
| 磁盘 | SSD，预留 30～50GB 给编辑器、项目缓存和构建 |
| 软件 | Unity Hub、Unity 6.3 LTS、VS Code 或 Visual Studio、Git |

只安装 Windows 所需模块。Android SDK/NDK、iOS Build Support、Xcode、Linux Server、Docker 和数据库均不安装。

### 6.2 玩家建议配置

| 等级 | 操作系统 | CPU | 内存 | GPU | 存储 |
|---|---|---|---|---|---|
| 最低目标 | Windows 10 21H1 x64 | 双核/四线程 | 4GB | Intel UHD 630 或 DX11 同级 | 2GB |
| 推荐 | Windows 10/11 x64 | 四核 | 8GB | GTX 750/GT 1030 或更高 | 2GB |

最终最低配置必须在独立低配电脑上验证，不能只根据开发机推断。

## 8. 交付顺序

1. 工程骨架、固定 tick、配置校验和测试入口。
2. 单场景垂直切片：射击、一个敌人、城墙、胜负。
3. 三类敌人、三种基础技能、10 Stage、Boss。
4. 本地存档、升级、结算幂等、设置和本地化。
5. 性能、低配兼容、Windows 构建和 ZIP 发布。
6. MVP 通过后再评审 Windows 1.0 内容。

## 9. 发布门禁

- 所有 AT-001 至 AT-020 通过。
- Domain 测试覆盖核心胜负、伤害、资源和存档路径。
- 发布包不包含开发控制台、测试存档、绝对路径或个人信息。
- Windows x64 构建在无 Unity 编辑器的干净电脑上可运行。
- ZIP 包包含版本号、配置哈希、许可信息和最小运行要求。
- Backlog 功能没有以空按钮、不可用登录或联网错误暴露给玩家。
